# Безопасность

## Модель угроз

KnowTomorrow хранит чувствительный, но не медицинский дневник. Основные риски:

- утечка базы SQLite или резервных копий;
- подбор пароля и перебор сессий;
- CSRF на изменяющие запросы;
- XSS через заметки или импортированный JSON;
- утечка персональных данных через агрегаты;
- ошибка конфигурации HTTPS/cookie.

## Меры

- Пароли — scrypt (N=16384, r=8, p=1), соль 16 байт, `timingSafeEqual`.
- Сессии — 256-битный токен, в БД только SHA-256, TTL 30 дней.
- Cookie — HttpOnly, SameSite=Lax, Secure при HTTPS.
- CSRF — проверка Origin для POST/PUT/PATCH/DELETE.
- CSP — `default-src 'self'`, без inline-скриптов и внешних CDN.
- Rate limit — auth и запись состояния.
- Ограничение тела — 2 МБ.
- SQL — только prepared statements.
- XSS — экранирование всех пользовательских строк в DOM; SVG-атрибуты числовые.
- Импорт — нормализация и ограничения на даты/оценки/заметки.
- Агрегация — только opt-in, только средние, порог 5 участников, без записей.
- Логи — типы событий без содержимого дневника.
- Статика — защита от path traversal, ETag, CSP, HSTS за HTTPS.

## Что делать при инциденте

1. Остановить сервис.
2. Сохранить логи и копию БД для разбора.
3. Сменить все сессии: удалить таблицу `sessions` (пользователи перевойдут).
4. Проверить, не утекли ли резервные копии; удалить лишние.
5. Уведомить пользователей, если затронуты персональные данные.
6. Исправить причину и добавить тест.

## Известные ограничения

- Нет email-верификации и сброса пароля.
- Нет 2FA.
- Rate limit хранится в памяти процесса; при нескольких репликах нужен Redis.
- SQLite рассчитан на один инстанс.
- Резервные копии не шифруются автоматически; шифруйте на уровне хранилища.
- Нет автоматического аудита зависимостей, потому что зависимостей нет; следите
  за версией Node и ОС.
