# Научный метод и ограничения

Этот документ описывает, что именно считает KnowTomorrow, какие упрощения
допускает и почему интерфейс говорит «гипотеза», а не «предсказание».

## 1. Модель данных

Каждый день описывается вектором из семи оценок от 1 до 10:

```
x_t = (самочувствие, дом, работа, улица, погода, неживая природа, живая природа)
```

Общая оценка:

```
overall_t = Σ w_i · x_{t,i} / Σ w_i
```

Сумма берётся только по включённым и заполненным категориям, поэтому пропуск
одной сферы не обнуляет день. Веса `w_i` задаются пользователем через AHP.

## 2. AHP Саати и согласованность

Пользователь заполняет верхний треугольник матрицы `A` (7×7): насколько
критерий строки важнее критерия столбца. Нижний треугольник — обратные значения.

Веса считаются методом геометрического среднего строк:

```
w_i = (Π_j a_ij)^(1/n) / Σ_k (Π_j a_kj)^(1/n)
```

Затем:

```
λ_max = (1/n) Σ_i (A w)_i / w_i
CI = (λ_max − n) / (n − 1)
CR = CI / RI_n
```

`RI_n` — средний индекс случайной согласованности Саати; для n = 7 используется
`RI_7 = 1.32`. Порог `CR ≤ 0.10`.

Если CR больше порога, приложение перебирает все тройки критериев, считает CR
каждой 3×3 подматрицы и показывает тройку с максимальным CR. Это превращает
абстрактное «пересмотрите суждения» в конкретное действие: «проверьте три числа
между самочувствием, домом и живой природой».

Ограничение: AHP отражает **субъективные** суждения пользователя, а не
объективную важность сфер. Со временем веса можно менять; история пересчитывается
с новыми весами.

## 3. Признаки

Для каждой цели (общая оценка или отдельная сфера) строятся календарные признаки:

| Признак | Смысл |
|---|---|
| `lag1`, `lag2`, `lag3`, `lag7` | значение цели 1, 2, 3, 7 дней назад |
| `mean3`, `mean7` | среднее цели за последние 3 и 7 дней (минимум 2/3 наблюдения) |
| `dowSin`, `dowCos` | циклическое кодирование дня недели |
| `gap` | число дней с предыдущей записи |
| `ctx_*` | значения остальных сфер в предыдущий день |

Пропуски значений заменяются медианой тренировочной выборки. Для прогноза
используется только информация, доступная до целевого дня.

Модель обучается на последних 365 наблюдениях: дальше растёт время обучения, а не
качество. Паттерны и корреляции считаются по всей истории.

## 4. Модели

Для каждой цели обучаются и сравниваются четыре модели:

1. **Naive** — «завтра = сегодня» (последнее известное значение).
2. **Mean** — среднее по истории.
3. **Ridge-регрессия** — линейная модель на стандартизованных признаках с
   L2-регуляризацией `λ = 3`:

   ```
   β = (ZᵀZ + λI)⁻¹ Zᵀ y
   ```

   Ridge устойчива к мультиколлинеарности и малым выборкам.
4. **Gradient Boosting** — 14 небольших деревьев глубины 2, learning rate 0.08,
   минимум 5 наблюдений в листе. Деревья строятся по снижению SSE, без внешних
   библиотек.

Модель выбирается по MAE на walk-forward проверке. Если сложная модель не
улучшает MAE наивной более чем на ~1% (с допуском 0.01), выбирается более простая.
Это осознанная защита от переобучения на 10–30 наблюдениях.

## 5. Walk-forward проверка

Нельзя проверять модель на тех же днях, на которых она обучалась. Поэтому:

- первые `max(4, min(21, 0.5·n))` наблюдений идут в начальное обучение;
- далее модель последовательно предсказывает следующий день, обучаясь только на
  предыдущих;
- для скорости проверяются последние ≤ 14 шагов;
- для каждого шага считаются ошибки всех четырёх моделей.

Метрики:

```
MAE = mean(|y − ŷ|)
RMSE = sqrt(mean((y − ŷ)²))
```

Сравнение выбранной модели с наивной — парный t-тест по абсолютным ошибкам на
одних и тех же шагах. Дополнительно показывается улучшение MAE в процентах.

Если улучшение незначимо, интерфейс так и пишет. Это нормальный результат для
малых данных, а не повод показывать красивую цифру.

## 6. Интервалы и уверенность

Интервал — не формальный доверительный интервал модели, а **эмпирический
интервал ошибки**:

```
spread = 1.28 · max(RMSE_residual, 0.65)
low = value − spread
high = value + spread
```

Он ограничен шкалой 1–10. Уверенность — эвристическая оценка, зависящая от
числа наблюдений, MAE и числа проверочных шагов. Если проверка не показала
преимущества над наивной моделью, уверенность понижается до «средней» или
«низкой»; если проверки нет — до «низкой».

## 7. Холодный старт и популяционные приоры

При < 5 наблюдениях бессмысленно обучать персональную модель. Используется:

```
value = α · personalMean + (1 − α) · priorMean
α = n / (n + 6)
```

где `priorMean` — анонимное среднее по участникам, давшим согласие, или
нейтральные 5.5, если выборка меньше 5 человек. При 5–13 наблюдениях работает
среднее/климатология; персональные модели подключаются позже.

Популяционные приоры считаются **по средним каждого пользователя**, а не по
всем записям подряд, чтобы активные участники не доминировали. Наружу отдаются
только агрегаты; порог `MIN_PRIOR_USERS = 5`.

## 8. Общая оценка как композиция

Вместо отдельной «чёрной» модели общей оценки используется взвешенная сумма
покритериальных прогнозов:

```
overall_hat = Σ w_i · forecast_i / Σ w_i
```

Преимущества:

- видно, какая сфера тянет оценку вверх или вниз;
- общая оценка согласована с покритериальными;
- легче объяснить пользователю.

Для проверки качества общей оценки всё равно запускается отдельная walk-forward
проверка цели `overall`; её метрики показываются в блоке «Модель против наивного
прогноза».

## 9. Паттерны и множественные сравнения

Для каждой сферы и лага 1–3 считается корреляция Пирсона между значением сферы
в день `t` и общей оценкой в день `t + lag`. Дополнительно сравниваются
следующие дни после «низких» (≤ 4) и «высоких» (≥ 8) значений с остальными:

- разница средних;
- размер эффекта Коэна d;
- Welch t-тест.

Так как проверок много (7 сфер × 3 лага + эффекты), p-значения проходят
поправку Benjamini–Hochberg. В интерфейсе показываются и p, и q. Даже q < 0.1
не означает причинность: это исследовательская связь, которую можно проверить
на новых данных.

## 10. Валидация на пользователях

`scripts/research-report.mjs` читает JSON-экспорты и считает:

- MAE/RMSE наивной и выбранной модели на walk-forward;
- среднее и медианное улучшение;
- долю участников с улучшением;
- парный t-тест по MAE участников;
- отдельно фиксированную Ridge-модель.

Протокол и ограничения: [`RESEARCH.md`](RESEARCH.md).

## 11. Ограничения

1. **Мало данных.** До 14–20 записей оценки нестабильны; 7 дней — минимум для
   первых связей, а не для уверенных выводов.
2. **Самоотчёт.** Настроение и события субъективны; возможна ретроспективная
   реконструкция.
3. **Пропуски.** Календарные лаги требуют соседних дней; при редких записях
   признаков меньше.
4. **Нестационарность.** Связи могут меняться со временем; модель не
   переобучается автоматически на каждом новом дне, а пересчитывается при
   открытии прогноза.
5. **Смещение выбора.** Модель выбирается по тем же walk-forward данным, на
   которых считается улучшение; это оптимистичная оценка.
6. **Нет причинности.** Корреляция и различие групп не доказывают, что событие
   вызвало изменение.
7. **Нет медицинского смысла.** Приложение не диагностирует и не рекомендует
   лечение.
8. **Популяционные приоры** могут быть смещены составом участников; они
   используются только как стартовый ориентир.
